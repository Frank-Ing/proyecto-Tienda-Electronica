# Arquitectura del backend

## 1. Arquitectura de tres capas

```text
Cliente HTTP
    ↓
Routes / Middleware / Controllers
    ↓
Services
    ↓
Repositories
    ↓
PostgreSQL
```

## 3. Responsabilidades

### Routes

Registran las rutas, middleware y controladores de cada recurso.

### Controllers

Traducen solicitudes HTTP a llamadas de servicio y construyen respuestas HTTP. No contienen consultas SQL.

### Services

Implementan autenticación, autorización, reglas de productos y coordinación de repositorios.

### Repositories

Contienen exclusivamente operaciones de persistencia y consultas parametrizadas a PostgreSQL.

### Middleware

Valida JWT, captura errores y agrega información autenticada al contexto de Hono.

## 6. Consideraciones para Vercel

- Exportar la instancia de Hono como `default`.
- No ejecutar un servidor persistente con `listen()`.
- Mantener las funciones sin estado.
- Reutilizar la conexión o pool de PostgreSQL entre invocaciones cuando sea posible.
- Configurar todas las variables de entorno desde el panel de Vercel.
- Usar Node.js Runtime por la dependencia `bcrypt`.
