# Especificación funcional del backend

## 1. Alcance

La API permitirá a un administrador autenticarse y realizar operaciones CRUD sobre productos de una tienda de electrónica.

## 2. Recursos

### Administrador

- `identificador`
- `usuario`
- `contrasena` almacenada como hash bcrypt

### Producto

- `identificador_producto`
- `modelo_producto`
- `precio`
- `stock`
- `categoria`

Las categorías válidas son: `celular`, `laptop`, `monitor`, `teclado`, `mouse` y `audifonos`.

## 3. Endpoints

### Autenticación

#### Inicio de sesión

```text
POST /api/auth/login
```

Recibe usuario y contraseña. Devuelve un JWT cuando las credenciales son válidas.

#### Cierre de sesión

```text
POST /api/auth/logout
```

Requiere un JWT válido. El cliente deberá eliminar el token. Si se requiere invalidación inmediata en el servidor, se añadirá posteriormente una lista de tokens revocados o un sistema de refresh tokens.

### Productos

Las operaciones de escritura requieren el encabezado:

```text
Authorization: Bearer <token>
```

#### Registrar producto

```text
POST /api/products
```

#### Actualizar producto

```text
PATCH /api/products/:id
```

#### Eliminar producto

```text
DELETE /api/products/:id
```

#### Obtener un producto

```text
GET /api/products/:id
```

Este endpoint es público.

#### Listar productos

```text
GET /api/products
```

Este endpoint es público para permitir mostrar el catálogo.

#### Filtrar productos

```text
GET /api/products?modelo=<texto>&categoria=<categoria>
```

Los filtros serán opcionales y combinables.

## 4. Reglas de validación

- `usuario`: obligatorio, máximo 15 caracteres.
- `contrasena`: obligatoria en el login.
- `modelo_producto`: obligatorio.
- `precio`: número mayor que cero.
- `stock`: entero mayor o igual que cero.
- `categoria`: uno de los seis valores permitidos.
- `id`: entero positivo.

## 5. Respuestas

La API usará JSON con formatos consistentes:

```json
{
  "data": {},
  "message": "Operación exitosa"
}
```

Los errores seguirán este formato:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Los datos enviados no son válidos",
    "details": []
  }
}
```

## 6. Códigos HTTP

- `200`: consulta o actualización exitosa.
- `201`: recurso creado.
- `204`: recurso eliminado sin contenido.
- `400`: solicitud inválida.
- `401`: falta autenticación o token inválido.
- `404`: recurso no encontrado.
- `409`: conflicto.
- `422`: error de validación.
- `500`: error interno.
